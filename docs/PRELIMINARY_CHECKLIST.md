## A. 时间与账号

- [ ] 官方公开页只确认 **2026-08-16（北京时间）** 截止；登录提交页核对具体时刻，并尽量在当日白天完成提交，不把上传留到最后。
- [ ] 使用最终参赛账号登录，确认姓名、学校、手机号/邮箱及参赛资格真实有效。
- [ ] 团队总人数不超过 3 人；队长、成员和分工均正确。
- [ ] 提交前再次确认成员名单；官方规则提示提交后成员锁定，不以“之后再改”为前提。
- [ ] 查看页面是否显示初赛结果公布时间（当前公开信息为 2026-08-24）及通知渠道。

## B. 必交材料

- [ ] 项目名称控制在表单要求内（提交稿按 **20 字以内**准备），页面、文件名和项目介绍使用同一名称。
- [ ] 项目介绍不超过 **500 个中文字符**；包含具体用户、痛点、四 Agent 闭环、Skill/ECP 差异点、运行证据和当前边界。
- [ ] 方案 PPT 或 PDF 可打开、字体正常、无裁切、无空白页；优先同时准备原始 PPTX 与稳定 PDF。
- [ ] 方案按官方内容框架覆盖：一页总览、场景、方案、多 Agent、Skill、工程安全审计、开源、里程碑、团队。
- [ ] 必交 PDF 本身含可定位的 fresh-run 入口与单 Run 回执，不把所有运行证据只藏在可选 ZIP 中。
- [ ] 在另一台电脑或无本地字体环境抽查 PDF；文件大小和格式符合提交页限制。

## C. 选交材料

- [ ] 若上传源代码包，确保解压后可运行，README 启动步骤与实际一致，并排除 `work/`、缓存、本地数据库、密钥和第三方仓库副本。
- [ ] 若上传演示视频/链接，先在未登录或访客环境验证可访问性；不要把其写成官方必交项，除非提交页明确要求。
- [ ] GitHub 公开仓库、v0.3.1 Release、固定 commit 与资产 SHA-256 在截止前可访问，并与提交包一致；用未登录浏览器复核链接。
- [ ] 选交代码中的测试数、Golden 数、CRD 数和 PPT 数字完全一致。

## D. 五项评分权重自检

| 官方维度 | 权重 | 提交前问题 | PolicyFlow 主要证据 |
|---|---:|---|---|
| 场景价值 | 25% | 是否说清用户、风险成本、真实流程与跨场景复用，而非泛化“提效”？ | 报销合规主流程；临时生产权限第二场景；可观测阻断/回执 |
| 多 Agent 协作 | 25% | 是否证明至少 3 Agent 的职责和权限不可互换，并有异常闭环？ | Planner、Policy、Executor、Verifier；双 Human；拒绝/恢复/回滚 |
| Skill 工程 | 25% | 是否在必交方案里展示核心 Skill 的完整契约和复用边界？ | 6 个 Skill；`guarded-execute`；ECP 不变层与工具适配层 |
| 工程/安全/审计 | 20% | 是否有本地可复现证据，而非只给架构图？ | 测试、Golden/攻击用例、签名审批、幂等、checkpoint、Trace、审计包 |
| 开源贡献 | 5% | 是否说明协议、依赖、运行方式和真实公开状态？ | Apache-2.0、自有源码包、第三方声明；公开 Release 状态如实标记 |

## E. Agent Infra 硬要求映射

- [ ] **Agent 数量**：至少 3 个。PolicyFlow 为 4 个 Agent；双 Human 是审批角色，不用来凑 Agent 数。
- [ ] **Identity**：方案正文或附录覆盖每个 Agent 的 Name、Role、Capabilities、Inputs、Outputs、Dependencies、Decision Boundary、Trace 八字段。
- [ ] **AgentTeams 五能力**：逐项写明角色编排、任务拆解、上下文传递、协同执行、状态跟踪分别如何落地。
- [ ] **运行状态诚实**：v1.2.2 CRD 7/7 静态校验与真实 `agt apply` 已完成；4 Worker `Running`、Team `Active (3/3)`、2 Human `Active`，Matrix 6/6 handoff 可定位。仍明确标注 SQLite/MCP 状态桥、受控制度包同步和 Skill 分发/热加载为 GAP。
- [ ] **Skill**：至少一个核心 Skill 展示场景、输入、输出、触发、依赖、失败、安全和复用；其余 Skill 有组合关系。
- [ ] **Context**：至少两种机制可见。PolicyFlow 展示版本化制度检索、共享 Run/SQLite checkpoint、Trace；说明谁写、谁读、何时冻结、如何恢复。
- [ ] **高风险闭环**：Human 审批绑定具体计划与实际参数；Executor 无自批权；Verifier 无写权限；拒绝、崩溃、重放、并发和回滚都有结果。
- [ ] **差异化证据**：ECP 把政策引用、审批角色、工具参数、后置验证和补偿声明绑定到同一 Trace；关键主张至少有 E3 证据。

## F. 一致性与诚实性

- [ ] 项目名、版本号、Agent/Skill/测试/CRD 数字在介绍、PPT/PDF、README、演示和源代码包中一致。
- [ ] 不写“已接真实 ERP/SSO”“已在 AgentTeams 生产运行”“hash chain 绝对不可篡改”等超出证据的表述。
- [ ] 合成演示数据、模拟工具适配器、本地 HMAC、AgentTeams 相关 ID dry-run 与 fail-closed 负向证据均有显著边界说明。
- [ ] 第三方依赖、许可证与上游链接见 `docs/THIRD_PARTY_NOTICES.md`；模型/云 Skill 状态不做未经确认的强制性声明。
- [ ] 所有截图可辨认；二维码、短链、仓库链接和视频链接逐一打开验证。
