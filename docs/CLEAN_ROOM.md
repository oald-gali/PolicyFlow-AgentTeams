# Clean-room 复用声明

PolicyFlow 使用两个既有比赛项目中验证过的通用工程思想，但所有领域数据、接口、规则、测试案例和实现均为独立重写。

## 来自既有经验的方法

- 天池项目：文档归一化、版本指纹、证据预算、追加式调用账本、lineage 和风险复核。
- 讯飞项目：先发现工具 Schema 再规划、查询/写入意图区分、歧义阻断、Decimal、幂等、确认门、状态历史和改写测试。

## 没有迁移的内容

- 原比赛题目、文档、答案、调用日志、榜单规则或目标 Token 范围。
- 固定流程 ID、字段 ID、用户 ID、项目编码、人员、日期和金额。
- 针对隐藏测试或具体句子的特殊分支、替换表和回归补丁。
- 原项目代码、缓存文件和常量。

PolicyFlow 的政策 `PF-TRAVEL-2026`、四个场景、工具契约、测试和 UI 均为本次项目独立创建。旧项目只做只读检查，没有被本项目 import 或作为运行依赖。
